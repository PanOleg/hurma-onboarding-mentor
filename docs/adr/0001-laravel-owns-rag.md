# 0001. Laravel володіє RAG

Дата: 2026-10-06. Статус: прийнято.

## Контекст

Hurma System працює на PHP і Laravel, тому команда підтримуватиме саме цей код. Для RAG потрібні вилучення тексту з PDF і DOCX та обчислення ембедингів, а для цього найзручніші бібліотеки Python. Усі доменні рішення (аудиторії, статуси, права, цитати, прогалини) прив'язані до моделей і політик Laravel. Потрібно визначити, де живе оркестрація RAG і що лишається окремим сервісом.

## Рішення

Увесь RAG-пайплайн (нарізка, пошук, промпти, виклики LLM, цитати, grounding) живе в Laravel. Python-сайдкар `embedder` без стану й без бази надає лише `/embed` і `/extract-text`, а також `/health`. Він працює з текстами й файлами та нічого не знає про користувачів, документи чи аудиторії.

## Альтернативи

| Варіант | Плюси | Мінуси | Чому відхилено |
|---|---|---|---|
| Python володіє RAG (Laravel лише проксі) | Багата екосистема RAG-бібліотек | Дві кодові бази з доменною логікою, дублювання прав і аудиторій, команда Hurma підтримує PHP | Розмиває відповідальність, ускладнює безпеку аудиторій |
| Laravel без Python | Один стек, простіший деплой | Слабкі PHP-бібліотеки для PDF і локальних ембедингів | Не дає якісного вилучення тексту й локальної моделі |

## Наслідки

Простіше: одна точка правди для прав доступу й доменних правил, тести з фейками (`EmbeddingProvider`, `TextExtractor`, `LlmClient`) без мережі, сайдкар легко замінити. Складніше: потрібен мережевий виклик на кожен ембединг і витягування тексту, є ще один сервіс у Compose. Моніторити: доступність і затримку сайдкара, помилки `embedder_unavailable` та `extractor_unavailable`.
