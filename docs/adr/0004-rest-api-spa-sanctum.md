# 0004. REST API і Vue SPA з Sanctum cookie

Дата: 2026-10-06. Статус: прийнято.

## Контекст

Hurma використовує Vue на фронті, а чат із потоковою відповіддю та історією розмов найзручніше будувати як SPA. Потрібна проста автентифікація для браузера без зберігання токенів у localStorage. API має бути зрозумілим окремо від інтерфейсу, щоб його можна було тестувати Feature-тестами й описати контрактом.

## Рішення

Laravel віддає REST API під `/api/v1` у JSON, а Vue 3 SPA (Vuetify, Pinia) звертається до нього. Автентифікація за допомогою Sanctum SPA cookie з CSRF через `/sanctum/csrf-cookie`. Помилки мають єдиний формат `{"error": {"code", "message", "details"}}`.

## Альтернативи

| Варіант | Плюси | Мінуси | Чому відхилено |
|---|---|---|---|
| Inertia.js | Менше коду, без окремого API | Зв'язує фронт із Laravel, гірше підходить для SSE і окремого контракту API | Чіткий REST-контракт важливіший для тестів і презентації процесу |

## Наслідки

Простіше: чітка межа між фронтом і бекендом, API тестується незалежно, cookie-сесії безпечніші за токени у браузері. Складніше: потрібні налаштування CSRF і домену cookie, а дані для сторінок доводиться отримувати окремими запитами. Моніторити: помилки 419 та 401 на клієнті, узгодженість формату помилок.
