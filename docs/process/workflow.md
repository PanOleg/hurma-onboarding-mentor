# Процес роботи: Spec-Driven Development з агентом

Дата: 2026-10-06.

## Цикл задачі

1. Задача в плані посилається на AC-ідентифікатор і розділ спеки.
2. Агент отримує skill і контекст, пише тест, що падає, потім реалізацію, і запускає перевірку, описану в skill.
3. Людина рев'ює diff. Кожне виправлення записується в журнал сесії одним рядком: що пішло не так, яке правило додано в CLAUDE.md або skill.
4. Коміт із посиланням на AC, CI зелений.

## Skills агента

| Skill | Одна дія | Перевірка |
|---|---|---|
| `laravel-feature` | міграція, модель, Policy, Form Request, Resource, Feature-тест за описом ресурсу зі спеки | `php artisan test --filter=<Name>` |
| `queued-job` | job з ідемпотентністю, tries/backoff, записом в `ingestion_runs`, тест на failed-гілку | `php artisan test --filter=<Job>` |
| `vue-screen` | Vuetify-екран, Pinia-стор, API-клієнт за контрактом розділу 8, vitest на стор | `npm run test -- <store>` |
| `prompt-change` | нова версія файлу промпту, оновлений snapshot, `rag:eval`, запис у `04-evals.md` | `php artisan rag:eval` |
| `adr` | ADR за шаблоном: контекст, рішення, альтернативи, наслідки | рев'ю |

## Правило запису в журнал сесії

Журнали лежать у `docs/process/sessions/YYYY-MM-DD-*.md`. Один рядок на кожне виправлення, яке зробила людина після агента, у форматі:

`| задача | що зробив агент не так | яке правило додано |`

Правило, додане за результатом виправлення, потрапляє в `CLAUDE.md` або у відповідний skill, щоб помилка не повторилася. У журналі не буває секретів і реальних персональних даних.
